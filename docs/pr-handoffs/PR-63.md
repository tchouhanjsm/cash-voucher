## Security and failure review

- The existing `config.js` contains a Web App URL, but its current live project/deployment identity cannot be proven from repository source alone.
- `.clasp.json` and `.clasprc.json` are intentionally ignored by Git. Never commit Clasp credentials or deployment secrets.
- `clasp push` uploads source; it does not by itself prove the intended Web App version is live.
- `setup()` creates/configures sheets and folders, initializes an owner when Users is empty, and replaces the daily backup trigger. It is not a routine deployment command.
- No live Google project was accessed, no Clasp command was executed, no source was uploaded, and no production data was modified by this PR.

## Verification evidence

- Documentation-only change; CI and Browser E2E are required on the exact final PR head before merge.
- Local `npm run check`, `npm run test:e2e`, and `git diff --check` were not run in this connector-only environment.
- Live deployment, Google permissions, Script Properties, backup and restore are intentionally not claimed as verified.

## Residual risks / not verified

- The owner's local Clasp authentication and target project have not been inspected.
- The deployment ID in `config.js` has not been matched against the deployment list for the selected script.
- It is unknown whether the intended target is a new/empty project or an existing project with data; that determines whether one-time setup is required. Do not assume.
- Live authorization, voucher writes, receipts, scheduled backup and restore remain unverified.

## Release boundary

This PR is documentation-only. It does not run `clasp push`, create/update a Web App deployment, run `setup()`, change Script Properties, alter production Sheets/Drive, merge itself, or claim production readiness.
