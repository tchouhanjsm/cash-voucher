# PR #73 — Escape report date-range HTML rendering

## Outcome

Ensure both formatted date-range labels in the Recorded Movement Report are escaped at the HTML insertion point. Add adversarial Browser E2E coverage for malformed client state that reaches the rendering path.

## Acceptance criteria

- Escape both `dmy(R.from)` and `dmy(R.to)` before inserting the labels into the report template.
- Regression test forces a hostile value through the date control's value getter, submits the invalid range, and verifies the SVG payload remains visible literal text.
- Assert no injected SVG element exists and the payload handler has not executed.
- Restore a valid date range and continue the existing report workflow tests.
- Update handoff, roadmap, PR index, release readiness and rendering-security audit.
- No backend/API/schema/dependency/production-data or Apps Script deployment changes.

## Security and failure review

- Pass 1: the report uses an HTML template for the heading. `dmy()` only rearranges date components and is not an HTML encoder. Escaping belongs at the output sink.
- Pass 2: the browser test supplies malformed state through the value getter and confirms no SVG node is created and no event handler runs. Normal date inputs constrain ordinary user entry, but rendering must still safely handle malformed/tampered state.
- The invalid-range flow should preserve honest validation feedback. The test resets the date filter to a valid month-to-date range so subsequent assertions remain independent.
- Remaining active template sinks are still under the source-by-source security audit; this is not an XSS certification.
