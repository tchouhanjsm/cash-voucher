# PR #59 — Reporting and workflow automation contract

## Outcome

Provide a reviewable, durable contract for accounting exports and application workflow automation before introducing destination-specific accounting fields, scheduled financial behavior, or new roles. Reserve PR #60 for a cross-functional retrospective of merged code and evidence.

## Acceptance criteria

- [ ] Reporting/export requirements distinguish the current latest-200 audit CSV from a complete accounting export.
- [ ] Destination-specific export is blocked until the owner selects a target and an accountant validates a representative import template.
- [ ] Voucher status/inclusion, date/amount conventions, tax-field ownership, duplicate-import handling and reconciliation requirements are explicit.
- [ ] Automation candidates are ranked without representing proposals as shipped features.
- [ ] Every future automation must define trigger/timezone, authorization, idempotency, visible status, failure/retry, auditability, privacy and disable controls.
- [ ] Daily cash close remains blocked until `docs/DAILY-CASH-CLOSE-DESIGN.md` is approved by the owner.
- [ ] PR #60 is documented as a review/backlog phase, not a catch-all implementation PR.
- [ ] Roadmap, requirements, UI/UX review, engineering handoff and PR index are updated.
- [ ] No application code, API, schema, dependency, scheduled trigger, deployment or production data changes.

## Security and failure review

- No new endpoint, permission, scheduled trigger, secret, external integration or production behavior is introduced.
- Server-side authorization remains the security boundary.
- Any future automation must be idempotent, fail visibly, avoid duplicate financial records, preserve auditability and be disableable by an authorized owner.
- Exports must use spreadsheet-formula neutralization for untrusted text and must disclose their scope/completeness.
- Cash-close and destination-specific accounting behavior are explicitly gated; no tax fields or roles are inferred.

- Owner review and merge are required.
