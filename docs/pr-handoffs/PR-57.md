## Outcome

Manager and owner users can identify payment versus receipt entries more quickly and reach register actions more easily on a phone. At widths up to 800 CSS pixels, register rows reflow into readable card-like records, filters use a compact grid, and row actions are grouped with an accessible label.

## Acceptance criteria

- Voucher rows display explicit `Payment` or `Receipt` identity without inferring physical cash impact from the label.
- Receipt, print, edit and cancel actions remain tied to the existing visibility rules and active status.
- Action groups have an accessible name associated with the voucher number.
- At 390px, manager-facing row actions have at least 44px height and register has no page-level horizontal overflow.
- Desktop rows keep the existing table presentation with flex-grouped actions.
- Browser regression tests cover type identity, action group semantics, target dimensions, and responsive overflow.
- No backend/API, authorization policy, voucher schema, accounting, persistence, or deployment behavior changes.
