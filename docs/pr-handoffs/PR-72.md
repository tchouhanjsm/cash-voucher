# PR #72 — Recorded Movement Report browser flight coverage

## Outcome

Exercise the finance-facing Recorded Movement Report through the browser and
mock API, proving that filters and CSV export operate on the selected source
rows rather than merely documenting the feature.

## Acceptance criteria

- [x] Browser E2E visits the report through manager navigation and checks its
      scope disclosure and payment/receipt summary.
- [x] Default active report shows active source records and excludes cancelled
      records.
- [x] Cancelled-only filtering returns cancelled records and CSV preserves
      cancellation status and reason.
- [x] Receipt-only active filtering returns receipt records only; its CSV
      matches the selected filter.
- [x] Update handoff, roadmap, PR index, release readiness and rendering audit
      baseline, plus the dedicated PR handoff.
- [x] No runtime/backend/API/schema/dependency/deployment/production-data
      changes.

## Security and failure review

- The report UI uses the existing mock-backed browser harness; the change adds
  assertions, not new runtime behavior.
- The CSV assertions verify selected rows and cancellation metadata. Existing
  CSV unit tests separately cover formula-prefix neutralization and quoting.
- Report values and totals remain operational voucher movement, not proof of
  physical cash, profit, bank balance or tax liability.
- Two-pass review: functional review checks filtering/render/export consistency;
  adversarial review checks that assertions fail if cancelled rows leak into
  active results or export data diverges from selected filters.
