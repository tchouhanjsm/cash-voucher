# PR 64 Handoff — Owner-only voucher data-quality scan

## Outcome
Add a working, owner-only scan for structurally inconsistent voucher records and display actionable source-linked exceptions in Settings.

## Acceptance criteria
- Backend enforces owner-only access independently of UI visibility.
- Scan identifies missing voucher ID/vendor/category/creator, invalid date/amount/type/status, invalid voucher number, duplicate voucher number within the same type, and duplicate ClientID.
- Response includes source voucher ID/number/date/type, field, stable issue code, severity and message; output is capped at 500 details while total counts remain accurate.
- UI uses text nodes for returned data, has loading/failure/empty states, and clearly states this is not tax or accounting certification.
- Tests cover role denial and seeded exception detection.
- No schema migration, data repair, tax logic, physical cash inference or production deployment.

## Implementation
- `backend/Code.gs`: `dataQualityReport` action and source-row checks.
- `frontend/features/administration.js`: Settings scan card, safe DOM-rendered results.
- `frontend/main.js`: scan action registration.
- `test/test-backend.js`: owner-only and synthetic exception regression cases.
- Runbook/handoff/roadmap updated to reflect PR #63 deployment and unresolved live gates.

## Verification evidence
Local CI/browser workflows must run on the exact PR head. The user's current local Browser E2E command failed to start because Playwright is missing; do not treat that as a passing test. Connector-only authoring does not run repository tests locally.

## Security and failure review
- Owner permission is checked on the server using the existing `settings` permission.
- No write action or source-row mutation is performed by the scan.
- UI uses `textContent` for values returned from the backend.
- Scan is capped at 500 detailed issues to bound response size.
- It does not prove that amounts are financially correct or cash-settled.

## Release boundary
No Apps Script push/deployment, setup, schema migration, production-data mutation, or merge is performed by this PR.

## Residual risks / not verified
- Legacy records may contain historical issues; this report exposes them but does not repair them.
- Apps Script live performance at high row counts is not measured.
- Browser E2E and live Google role checks must pass/be witnessed before release.
- npm reported high-severity dependency findings; dependency paths require separate triage.
