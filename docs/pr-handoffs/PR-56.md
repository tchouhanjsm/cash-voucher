## Outcome and acceptance criteria

- The primary save action clearly matches the selected task: `Save payment(s)` or `Save cash receipt(s)`.
- Singular/plural save wording follows the number of rows with entered details; blank rows do not inflate the count.
- The post-save confirmation uses the same payment/cash-receipt terminology and provides a polite status announcement.
- The offline saved-on-device message and next action preserve the selected task terminology.
- Save and payment/cash-receipt mode controls are at least 44px high.
- Browser E2E verifies the workflow labels and target dimensions at 320 CSS pixels.
- No backend/API, authorization, voucher schema, accounting semantics, persistence contract, or production behavior changes.
