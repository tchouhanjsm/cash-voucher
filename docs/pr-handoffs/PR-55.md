## Outcome and acceptance criteria

- Register refresh shows a disabled, accessible busy state while bootstrap is in progress.
- A failed manual refresh displays an actionable error and restores the refresh button for retry.
- Receipt loading exposes an announced loading status per receipt.
- A receipt fetch/image-validation failure displays a useful error and a retry action.
- A successful retry replaces the failure state with the image; failed content is not cached.
- No backend/API, authorization, voucher schema, accounting semantics, persistence or production behavior changes.

## Implementation

- `frontend/features/navigation.js`: busy state around register/manual refresh and deterministic restoration on failure.
- `frontend/features/register.js`: receipt-specific loading status, DOM-created image/error UI and retry control; guard against empty file input.
- `style.css`: small layout rules for receipt loading/error states.
- `test/e2e.py`: simulate one transient getReceipt failure and one bootstrap failure; assert retry and refresh control recovery.
