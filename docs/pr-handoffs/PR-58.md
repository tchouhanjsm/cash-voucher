# PR #58 — Owner audit discoverability

## Outcome

Owners can open Audit log directly from navigation instead of locating it at the bottom of Settings. The view supports search, user/action filters, date bounds, filter reset, and CSV export of the currently filtered events.

## Acceptance criteria

- Audit navigation is shown only when the client session has the existing `audit` capability; the backend `auditLog` authorization remains the actual security boundary.
- Settings remains focused on property configuration and backup/recovery status.
- Audit values are rendered as text, not executable HTML.
- Search, user, action, and inclusive date filters compose predictably.
- The view clearly states that the existing API returns only the latest 200 events and that filters/CSV apply to that loaded window only.
- CSV export includes Time, User, Action, Target, and Details, escapes CSV cells and neutralizes formula-leading values using the existing `csvCell` helper.
- Clear filters restores all loaded events and empty states are explicit.
- Browser E2E covers owner navigation, filtering, clear filters, CSV download, and audit XSS inertness.
- No backend/API/schema/role/accounting changes, deployment, or production-data operation.

## Security and failure review

- No new backend endpoint or permission was introduced. Existing server-side `need_(user, 'audit')` remains authoritative.
- Hiding navigation is usability only, not access control.
- Audit data is inserted with `textContent`; user-controlled values are not interpolated into HTML templates.
- CSV uses the existing `csvCell` spreadsheet-formula neutralization helper.
- API failure produces an explicit unavailable state; the screen does not silently present an empty list as a successful load.
- Date filters compare the date portion of the returned ISO-like timestamp; timezone interpretation is not changed.
- The endpoint's 200-event ceiling remains a known limitation. Full-history pagination/search would require a separately reviewed backend/API change.

## Release boundary

- No merge, Apps Script push, deployment, live Drive operation, or production-data change has been performed.
- Owner review and merge are required.

## Residual risks / not verified

- The existing backend only returns the latest 200 events; this UI does not fetch older history.
- Live authorization, real Google service behavior, screen-reader output and physical-device usability remain unverified.
- CSV download was added to mocked Browser E2E; accountant compatibility and downstream spreadsheet behavior are not certified.
