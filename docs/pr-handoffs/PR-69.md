# PR #69 Handoff — DOM-only modal rendering

## Outcome

Remove the shared modal's raw HTML body-string contract so persisted or user-controlled values in modal content are built through DOM APIs rather than interpolated into HTML templates.

## Acceptance criteria

- `dialog()` accepts only a DOM Node or DocumentFragment and rejects strings before changing modal state.
- Migrate every current `dialog()` caller: PIN reset, forced PIN change, voucher edit, voucher cancellation and receipt viewing.
- Build category options, vendor datalist options and vendor summary text using DOM APIs and safe DOM properties.
- Retain existing Browser E2E hostile-vendor coverage through voucher edit and cancel dialogs; assert no injected `img`/`svg` nodes and no payload execution.
- Update the rendering-security audit, roadmap, engineering handoff, PR index and this handoff.
- Do not change backend/API/schema/dependencies, Clasp deployment or production data.

## Changes

- `frontend/core/ui.js`: validate modal body is a DOM node/fragment, render only the static modal shell through the template, and insert body nodes before the error region.
- `frontend/core/form-options.js`: add DOM-based category-option and vendor-datalist builders while preserving existing string helpers for non-modal callers.
- `frontend/features/administration.js`: construct reset-PIN modal with DOM nodes.
- `frontend/features/auth.js`: construct forced PIN-change modal with DOM nodes.
- `frontend/features/register.js`: construct edit/cancel/receipt modal content with DOM nodes and safe property assignment.
- `docs/SECURITY-RENDERING-AUDIT.md`, `docs/PRODUCT-ROADMAP.md`, `docs/HANDOFF.md`, `docs/PR-HANDOFFS.md`: record the scope, status and remaining risks.

## Two-pass review

**Pass 1 — contract and data flow**

- All five current callsites in `administration.js`, `auth.js` and `register.js` are migrated to pass a `DocumentFragment`.
- User-derived text is assigned using `textContent`/text nodes; field values use DOM properties; category/datalist options are created as nodes.
- The dialog validates the body type before modal state is changed.
- Static modal title and submit label remain HTML-escaped; error messages remain text-only.

**Pass 2 — failure and compatibility review**

- DocumentFragment children are moved into the modal form before the error region; subsequent selectors still resolve from the modal.
- PIN change/reset required/pattern/autocomplete semantics are preserved.
- Edit form retains IDs and field names consumed by the existing submit callback; category selection is explicitly retained.
- Receipt file input, label, `aria-live` region and conditional add control are preserved.
- Residual concern: other active feature renderers still use template-based `innerHTML`; this is targeted modal hardening, not a full stored-XSS certification.
