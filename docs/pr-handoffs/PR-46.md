## Outcome

Ensure failed backups do not leave incomplete snapshots that look like valid recovery points, preserve completed snapshots when retention pruning fails, and always release a script lock if and only if it was acquired.

## Implementation

- Track backup snapshot completion only after the receipt manifest has been created.
- Trash a snapshot on a pre-completion failure; preserve it if later retention pruning fails.
- Bound recorded error metadata to 300 characters and include cleanup diagnostics when possible.
- Do not let a failure to write diagnostic metadata replace the original backup exception.
- Move lock acquisition and property access into the guarded orchestration; release in `finally` only after successful acquisition.
- Remove the arbitrary PR commit-count failure gate while preserving required handoff validation.
- Record the workflow and PR history so future threads can resume from verified GitHub state.

## Regression coverage

The focused orchestration suite exercises:

- Receipt copy and manifest creation failures.
- Cleanup failure without masking the original exception.
- Retention failure after completion, preserving the complete snapshot.
- Failure metadata writes that throw.
- Lock acquisition timeout without an invalid release.
- Property-service failure after lock acquisition, with correct release.
- Successful backup orchestration.

These are deterministic service-mock tests, not live Google Drive or Apps Script integration tests.
