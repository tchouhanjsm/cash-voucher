# PR #66 Handoff — Backup integrity inspection

## Outcome

Give the owner a bounded, read-only inspection of recent managed backup snapshots so obvious missing/corrupt structure is visible before a restore drill.

## Acceptance criteria

- Server-side owner-only authorization using the existing `settings` capability.
- Inspect no more than the ten newest folders matching the managed `backup-YYYY-MM-DD_HHmmss` naming pattern.
- Check spreadsheet copy presence and readability, required tabs, current header compatibility, receipt folder, manifest presence/readability/header, receipt count, unique manifest IDs and existence of each referenced copy in the receipt folder.
- Return per-snapshot pass/warning/fail checks and sheet row counts; do not return Drive IDs.
- Fail closed on inaccessible or unreadable snapshots.
- Treat schema-header mismatch as a compatibility warning rather than automatically claiming corruption.
- Provide a Settings UI action with loading/error/results states using safe DOM text rendering.
- Add injected-service regression tests for ordering, limit, missing copies, inspection failures and schema warnings.
- No restore, cleanup, pruning, file deletion, schema migration, setup, Clasp push, deployment or production-data mutation.

## Security and failure review

- Authorization is enforced server-side; Settings navigation alone is not access control.
- Scan is read-only and capped at ten snapshots; no Drive IDs are returned to the UI.
- Drive/Sheets inspection errors fail closed for the affected snapshot.
- Header mismatch is a warning because old snapshots may predate a schema change.
- The scan proves only observable structure, not recoverability or content correctness after restore.
